# Design: Square Footage — Go Live the `rectangle-area` Calculator (EN/ES)

This design implements `proposal.md` (D1–D10 are binding) and runs AGENTS.md recipe steps 11–14 for `rectangle-area`. The delta specs win over any value written here. Line forecasts come from reading the current files. The apply measures every byte and line figure and records it in `apply-progress.md`.

## Answer first

- **An inline style cannot carry the per-page reserve (D3 and its risk row now point here).** `CalculatorBody` accepts `style` today, but an inline style holds one value for every width. An area sentence ("A 12 ft by 10 ft area is 120.00 square feet.", 44–58 characters at about 10.3 px each) takes 2–3 answer lines at 320 px and 1 line at 1280 px. One count cannot satisfy [CP60] at both widths. The shared breakpoints do not help either: they are concrete's (24.125, 30.0625, 45.625 rem), and the area sentence drops to one line near 39 rem. Between those two points the reserve would hold one full unused line. **K6:** the `PAGES` row declares the counts per breakpoint. `CalculatorView` emits one `<style>` in the head of that page only, setting `.calculator{--answer-lines:…;--notice-lines:…}` and its media blocks. Concrete pages carry 0 extra bytes.
- **The notice reserve depends on the page too.** The not-running note is `noscript + ' ' + calc.<id>.page.example`. A shorter example than concrete's leaves more than one body line unused under the shared `--notice-lines` ([CP61]). So K6 carries `notice` as well as `answer`.
- **Two latent go-live breakers in the current tests:**
  - `pages.test.ts` reads the `SCRIPTS` keys with `^\s*([\w-]+):`, which cannot match the quoted key `'rectangle-area':`.
  - `CalculatorView.test.ts` derives the island name as `Rectangle-areaScript.astro`, but the recipe and the proof name `RectangleAreaScript.astro`.
  
  K7 fixes both before S4.
- **Pre-staging is limited by `satisfies Record<CalculatorPageId, …>`.** An object literal with an extra key is a type error. So the `PAGES`, `SCRIPTS` and `E2E` rows can only land at go-live. S3 pre-stages the mechanisms and the E2E module instead; the measured reserve constant and the `WIDTHS` edges are legal before the route (S4a).
- **The go-live is gated on the owner (K12).** S4 starts only after the owner's explicit approval of both entries is recorded in `apply-progress.md` (date, and where: chat or PR comment). No agent sets `ownerReview: approved` without that record.
- **Slices:**
  - S1 is about 540–620 lines and S3 about 560–640, so each splits in two. PR 1 = S1a + S1b, PR 2 = S2, PR 3 = S3a + S3b, PR 4 = S4a + S4b (about 240–330 lines; S4b is the one atomic go-live commit series).
  - The public site does not change until PR 4: PRs 1–3 must produce a byte-identical `dist`.

## Interfaces

```ts
// contract/__testing__/calculator-rows.ts
export interface ContentRow<Id extends ExampleId> {
  readonly module: AnyPageModule;
  readonly updated: string;
  readonly sources: (locale: Locale) => readonly { readonly name: RegExp | string; readonly url: string }[];
  readonly engine: (example: WorkedExample<Id>) => WorkedExample<Id>;
  readonly figures: (example: WorkedExample<Id>) => readonly string[]; // rectangle-area: [ft2, yd2, m2], not the query

// lib/reserve.ts
export type LineSteps = readonly [number, ...(readonly (readonly [rem: number, lines: number])[])];
export interface Reserve { readonly answer?: LineSteps; readonly notice?: LineSteps }
export const reserveCss: (reserve: Reserve) => string;
```

# Design Review: square-footage

Fresh-context architecture review of `proposal.md`, `design.md` and the seven delta specs on branch `feat/square-footage` (2026-10-27).

**Verdict: APPROVE WITH CHANGES.** The architecture holds (per-id tables for content, methodology and budget; the per-page head reserve of K6; the proof move of K9; the atomic go-live). Two blockers must change before tasks: the layout-stability text still prescribes the inline style that K6 replaced (B-1), and the Spanish answer sentence of [RAP2] cannot be produced by the language-free `dimensionText` (B-2). The majors and minors are wording, slice and process gaps. None reopens D1–D10 or the owner decisions.

## Reconciliation before tasks

Applied in this revision; see the Resolution column. Found while applying:

- The site-quality delta named the fixture `apps/web/src/views/budget-page.astro`; it is `apps/web/src/contract/__testing__/budget-page.astro` (fixed with m-6).
- A recipe path token with `<id>` is checked with `concrete` filled in (`docs.contract.test.ts:69-80`), so `calculator/<id>/reserve.ts` cannot be named as a path: concrete has no reserve (handled in K13).
- `tooling/site-browser` resolves only `@maestro-calc/i18n` (its `tsconfig.json` `paths`), so the e2e cannot import `PAGES`; the per-page `BEFORE_EDGE` reads the shipped CSS instead (m-7).
